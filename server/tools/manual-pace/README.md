# BOSS DOM 操作监控

运行根目录的 **手动节奏采样.cmd**，或运行 node server/tools/manual-pace/recorder.cjs --open。

1. 关闭自动投递桌面助手，点击「开始 DOM 监控」。工具复用项目专用 Chrome 和已有登录资料；只有页面监听器返回就绪确认，才开始记录。
2. 在 Chrome 中按平常方式选择岗位、阅读、查看公司、沟通和处理后续弹窗。无需逐步打点或手动分轮。
3. 下一次选择岗位自动结束上一轮并开始下一轮。建议连续浏览3–5个岗位，临时离开可暂停。
4. 最后点击「结束并保存」。末轮一并结束，监听器移除，Chrome 窗口保留。记录保存于 data/manual-pacing，可导出。
5. 告诉助手「采样完成」，再根据真实样本调整自动操作节奏；工具本身不修改生产参数。

自动采集可信点击、控件聚焦、输入动作（不采集值）、滚动、主页面导航及详情/公司页就绪。滚动事件180ms内合并，避免浏览器逐帧滚动淹没记录。详情就绪观察有约250ms延迟，分阶段阅读时间为近似值；每轮总时长以实际选岗点击为边界。输入在触发时记录，不等输入结束再计时。

记录字段限于操作类型、时间、DOM 标签/最多三个样式类、页面类别。岗位正文只用于本机判断详情是否显示，不导出正文、名称、链接、输入值、Cookie 或聊天内容。监听运行在独立脚本环境中，页面刷新后重新安装，新 BOSS 标签自动接入。首次打开时等待新文档的监听就绪确认，不将初始空文档当作安装成功。登录/验证页及浏览器断开会暂停记录，人工处理后可继续；不读取或解除生产任务的账号暂停状态。

工具仅被动监听，不代替用户选岗、沟通、投递或反馈。点击记录不证明消息发送成功。不会通过这份样本宣称能避免平台限制。旧版手动分轮文件保留，formatVersion:2、capture:dom 才是新监控记录。

验证：

- node --test server/tools/manual-pace/model.test.cjs server/tools/manual-pace/native-launch.test.cjs：时间边界、暂停、分位数、字段白名单和启动错误。
- node server/tools/manual-pace/recorder.test.cjs：临时资料目录及浏览器，全部页面请求离线拦截，验证真实 CDP 安装确认、DOM 事件、刷新、公司新标签、沟通页、自动分轮、登录暂停、移除监听和保存，不访问真实 BOSS 或投递。
- node server/tools/manual-pace/observer.test.cjs：页面监听分类与非可信点击隔离。

- node --test server/tools/manual-pace/monitor.test.cjs：初始空文档切换后延迟就绪、端口可连但无 DOM 握手时拒绝开始。
