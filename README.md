# BOSS 直聘求职与投递助手 (Boss-Job-Agent)

使用简历分析、岗位筛选和 BOSS 直聘网页 DOM 辅助求职。桌面由 Electron 主进程、隔离 preload、本地 React 界面和受管理的后台工作进程组成。界面通过桌面内部协议访问服务，BOSS 页面在独立 Chrome 窗口中打开。

---

## BOSS 网页接入

- 登录页和岗位页分开管理。Chrome 在专用资料目录保存扫码 Cookie；界面启动只观察已有窗口，不自动启动 Chrome、打开岗位或刷新页面。主动打开扫码页、验证或启动任务时才恢复会话。验证信息记在 `data/boss-session.json`，不包含 Cookie 值。浏览器连接故障、安全验证和登录失效分别提示。
- 新的 BOSS 页面模块按已登录页面的实际 DOM 识别职位卡片、右侧详情、登录提示和安全验证。空白页、加载中、明确无结果是不同状态；单有 `_security_check` 参数但职位卡片正常显示时仍按职位页处理。
- 批量操作按职位链接定位，发送前再次核对岗位和详情；没有确认沟通成功时停止任务并提示人工检查，避免继续批量操作。
- 旧的页面内 `fetch` 模拟接口已移除。BOSS 网站页面变动时，流程会停止并报告当前状态。
- 普通 Chrome 会话使用 `data/boss-profile-v3`。首次使用这个资料目录时需扫码一次，以后优先恢复已保存的会话。

## 🚀 快速启动

### Windows 桌面窗口

双击项目根目录的 [启动桌面版.vbs](启动桌面版.vbs)，即可在独立的 Electron 桌面窗口中使用现有的 React 控制台，包括批量投递、筛选设置和运行日志。首次使用请先运行 [启动桌面版-调试.cmd](启动桌面版-调试.cmd)，它会构建页面并启动窗口；之后可直接双击桌面入口。需要 Node.js、已安装项目依赖和 Google Chrome；桌面控制窗口本身不依赖 Python。

关闭窗口会先停止任务，再结束它启动的后台；桌面主进程意外退出时，后台也会停止。重新打开不会自动恢复投递。界面加载打包在项目中的本地资源，后台接口凭据只保留在主进程，BOSS 账号扫码仍在专用 Chrome 窗口中进行。项目目前通过 Electron 运行，尚未打包成独立安装程序。

再次双击入口会显示已有窗口，隐藏或最小化的窗口也会恢复。桌面启动测试：在项目根目录运行 `npm run test:desktop`，覆盖窗口恢复、渲染失败恢复、本地协议、隔离 preload、中文上传、流式日志、窗口指令和关闭时停止任务。

桌面窗口目录与启动锁按当前 Windows 账号区分，避免隔离测试账号阻挡日常账号启动。此目录只保存控制台的浏览器缓存；BOSS 登录资料、模型账号、配置和运行记录仍保存在原来的独立目录。

### 1. 运行环境
- Node.js 18+ (推荐 Node.js 20+)
- 已安装 Google Chrome（路径：`C:\Program Files\Google\Chrome\Application\chrome.exe`）

### 2. 启动命令
进入项目服务端目录：
```powershell
cd D:\boss直聘脚本\server
npm run dev
```

在浏览器打开：**[http://localhost:3001](http://localhost:3001)** 即可进入现代化可视化控制台！

> 服务默认只监听 `127.0.0.1`（接口无鉴权且持有大模型密钥与会话 Cookie，不应暴露到局域网）。
> 确需局域网访问时：`$env:HOST="0.0.0.0"; npm run dev`
>
> 基础自检：`npm run selftest`；投递入口、会话恢复和批量流程测试位于 `server/tests/`。

## 📖 使用指引

1. **连接 DeepSeek 网页**：在【设置】选择 DeepSeek 网页，点击【打开 DeepSeek 登录】并手动登录。窗口会自动验证并保存账号，保持显示直到你手动关闭；之后启动自动复用。再点击【保存并测试连接】确认 JSON 调用。此方式无需购买官方 API Key。
2. **选择投递方式**：在【开始投递】选择【用简历匹配岗位】或【手动指定目标】。简历路径上传简历后可直接开始，也可以先到【简历分析】获取推荐岗位；手动路径只需填写目标岗位和至少 10 个字的筛选要求。简历改写是可选功能。
3. **核对条件并启动**：【BOSS 职位来源】默认按目标设置「推荐」旁的自选岗位。在助手中选1至3个 BOSS 官方岗位，启动时会修改 BOSS 求职期望的岗位与城市，保存后刷新核对，再只遍历这些目标。已有匹配项优先保留；不足三个目标时其余 BOSS 期望不会被删除。全部留空时，AI 根据当前简历或求职要求选择官方方向。也可切换为官方分类和关键词搜索。每日数量、需求词和淘汰词在【筛选规则】中设置。
4. **处理网页登录提示**：首次使用专用 Chrome 资料目录时扫码一次；后续优先恢复保存的会话。若 BOSS 页面要求安全验证，需在 Chrome 中手动完成。任务进度、暂停与停止在【运行记录】中查看。页面没有出现可验证的“不合适”控件时不会尝试标记。

已在登录后的真实 BOSS 职位页验证会话恢复、职位卡片读取、岗位链接匹配、完整描述、自选期望切换和“不合适”反馈，平台成功提示为“已进行反馈”。离线页面测试覆盖沟通确认和批量控制；真实沟通发送尚未实投验证。页面结构记录见 [BOSS 页面 DOM 基线](docs/boss-dom-baseline.md)。

2026-10-02 已按当前目标将 BOSS 自选位置保存为“新媒体运营（上海）”，刷新后再次确认。三个位置的编辑、新增、城市切换和已匹配项保留通过页面模拟测试。运行记录显示当前目标、设置进度、脚本初筛、AI 批量分析、实际请求次数；新待确认记录显示评估来源与匹配分数。

薪资读取会还原 BOSS `kanzhun` 字体替换的0至9数字，显示和薪资初筛共用同一还原规则，未知字体字符显示“薪资待确认”。PDF 使用支持中文字体映射的解析器，并按文字位置重建阅读顺序；已用原始中文简历核对“工作经历”“教育经历”“资格证书”等标题。文本简历支持 UTF-8、带标记的 UTF-16 及 GB18030。上传的原文件保留。

职位卡片只用来打开岗位。筛选、AI、待确认和投递使用实际详情中的岗位名称、公司、薪资、学历、经验、要求及岗位链接，不要求这些文字与卡片完全一致。发送前重新读取详情，岗位资料发生变化时重新评估。

公司页没有公司介绍、职位未写明具体工作内容时，默认先在本地淘汰，不请求 AI、不加入待确认。这两项均可在【筛选规则】关闭。简短但写明具体工作动作和对象的描述可以继续筛选；未能读取公司页时保留待确认，不把网络失败误认为没有介绍。读取公司信息使用实际详情上的公司链接，同一公司短时间内复用核查结果。

对明确不符合的自选职位，程序在右侧详情点“不合适”，选择 BOSS 已提供的反馈选项，优先选择公司选项；内部分析理由保存在本地。收到平台成功提示才增加标记数；工作条件缺失或冲突的待确认岗位不会被当作明确不合适。

## 位置与通勤

在【筛选规则 → 位置与通勤】设置出发点：

- **获取当前位置**：主动调用 Windows 系统位置服务，显示返回的精度；先核对地图，再确认使用。系统权限关闭、无位置提供器或超时时，可直接搜索地点或在地图选点。
- **地图选点**：Leaflet + OpenStreetMap，无需申请个人地图 Key。点击地图选择准确出发点，填写名称并点击“使用此出发点”，最后保存筛选规则。城市中心只用来显示初始区域。
- **搜索位置**：使用免 Key 公共搜索（Nominatim），只在点击时请求，整个进程至少间隔1.1秒、缓存24小时，遵守 [Nominatim 使用政策](https://operations.osmfoundation.org/policies/nominatim/)，不做输入联想或批量岗位地理编码。个人地图 API 设置和调用已移除，旧 Key 在配置迁移时删除；原出发点及距离条件保留。
- GPS / OSM 与岗位坐标在本机统一后计算直线距离。公网 IP 或城市中心不会被自动当成真实出发点。公交／地铁仍读取 BOSS 实际路线，取得不了有效路线时保留待确认。
- 升级桌面时先停止旧版任务，再加载新版后台，避免旧版继续执行自动操作。

组件、系统定位限制与坐标依据见 [公开定位项目研究](docs/public-location-projects.md)，Leaflet 授权见 [第三方声明](client/THIRD_PARTY_NOTICES.md)。若部署自己的 OSM 瓦片或 Nominatim，可在启动环境设置 `LOCATION_TILE_URL`（HTTPS，含 `{z}/{x}/{y}`）、`LOCATION_MAP_ATTRIBUTION`、`LOCATION_SEARCH_URL`；无需更新软件代码。公共地图只请求当前手动查看的区域，按浏览器 HTTP 缓存保存，不支持预下载。

## DeepSeek 网页模型

已接入 [Chat2API](https://github.com/xiaoY233/Chat2API) 的 DeepSeek 网页适配器精简版本，在独立本机进程中运行。来源、固定版本、GPL 授权及修改记录见 [组件说明](vendor/deepseek-web-proxy/UPSTREAM.md)。

- 单账号顺序处理，请求从上一轮结束后默认等待30秒，可在设置中调整为10至300秒。深度思考与联网搜索分别设置，默认均关闭；可单独开启，也可同时开启。网页频率或额度受限时暂停任务，由用户检查后恢复。
- 使用已验证的网页默认模型，内部使用适配器标识 `deepseek-v4-flash`，实际发送网页参数 `model_type: default`。这个标识不代表已确认网页底层模型版本。AI 设置已移除 GLM 和 Pro 预设。
- 网页凭据使用当前 Windows 用户的 safeStorage 保存到 `data/deepseek-web-credential.json`，浏览器资料在 `data/deepseek-web-profile`；与 BOSS 会话独立。不会把旧 GLM Key 发送给网页代理。
- 不保存简历或模型正文到代理日志；JSON 依靠提示词与解析校验，网页接口没有原生 JSON 模式或输出 token 限制。
- 进入设置时自动准备本机服务；登录窗口关闭不会结束模型服务。退出空闲桌面助手会停止空闲代理，仍打开的登录窗口会继续保留。
- 也可以选择其他兼容 API 并手动填写地址、模型和对应 Key。网页账号与官方 API Key 是不同凭据。

校验：`node --test vendor/deepseek-web-proxy/tests/protocol.test.cjs`、`cd server; npx tsx tests/deepseek-web.test.ts`。真实 DeepSeek 调用需先由用户完成网页登录。

在“设置 → 网页功能”选择“深度思考”和“联网搜索”，点击“保存设置”。前者控制网页思考功能，后者允许网页模型检索相关信息；两者独立于本机模型标识。设置用于后续简历分析、改写及岗位匹配，不会修改自定义 API 的请求格式。网页登录窗口中手动切换按钮不会覆盖助手保存的选项。

### 反代与官方 API 的区别

当前调用链：求职助手 → 本机 `/v1/chat/completions` → `https://chat.deepseek.com/api/v0/chat/completion`。本机组件把 OpenAI 格式转换成网页聊天协议，再把网页返回内容包装成 OpenAI 格式。

它读取已保存的网页登录凭据，验证账号后创建临时聊天，完成网页要求的 PoW 请求校验，发送聊天内容并读取返回流。每次请求结束只尝试删除本次临时聊天。本机接口的密钥仅用于本机认证，与 DeepSeek 官方 API Key 无关。

| 项目 | 当前网页反代 | DeepSeek 官方 API |
| --- | --- | --- |
| 上游地址 | `chat.deepseek.com/api/v0/chat/completion` | `api.deepseek.com/chat/completions` |
| 认证 | 网页账号登录凭据 | 开放平台申请的 API Key |
| 请求转换 | 将消息转成网页提示词，返回流转成完整回答 | 直接使用官方兼容协议 |
| 本项目支持的接口 | OpenAI 格式的文本、非流式聊天；未实现 Anthropic 接口 | 官方提供 OpenAI 和 Anthropic 兼容入口 |
| 使用限制 | 跟随网页账号及网页接口限制 | 跟随官方 API 的额度与计费 |

截至 2026-10-01，[DeepSeek 官方文档](https://api-docs.deepseek.com/zh-cn/)列出的模型名为 `deepseek-flash` 和 `deepseek-v4-pro`；旧名 `deepseek-v4-flash` 的官方 API 请求由 V4.1-Flash 提供服务。这是官方 API 的模型规则，不能套用到本机网页适配器的同名标识上。网页底层模型由网站决定，本项目没有确认具体版本。

本机网页代理没有原生 JSON 模式、输出 token 限制或完整的 OpenAI 参数支持。若选择设置中的“其他兼容 API”，可填写官方地址 `https://api.deepseek.com`、模型 `deepseek-flash` 和官方 API Key，改为直接调用官方接口；这个入口使用 OpenAI 格式。

- `client/`：React 控制台；`server/`：配置、筛选与 BOSS DOM 投递服务。

## 学历筛选

在“筛选规则 → 我的最高学历”选择自己的学历。岗位学历按最低门槛比较：本科可匹配大专、专科、本科及学历不限岗位，硕士可匹配本科及以下岗位。明确限制学历的岗位保留其限制。不设置学历时不做这一项硬筛。

### 语言与必备资格

在“筛选规则 → 我的语言能力”填写实际掌握的语言、水平、证书和口音，也可从本次简历读取明确依据。手动求职要求中的愿望不会当成能力。先读完整描述区分硬要求、优先和可培训；必备语言没有达标依据时在本地淘汰，不请求 AI、不进入工作条件待确认，并在自选列表按实际原因反馈“不合适”。本次已用“哥斯达黎加数据标注”的真实描述及本机原简历验证零 AI 淘汰。

语言证书按实际等级核对；四级、六级等不会自动证明口语流利或掌握特定口音。AI 评估还会返回其他必备资格的失败原因和岗位原文；有效的资格失败优先于工时缺失的待确认，伪造引用、经验优先和普通加分项不能作为硬资格失败。新待确认记录只保留语言能力依据，不保存整份简历；旧记录重筛前备份。

验证：`cd server` 后运行 `npm run test:language`，覆盖26项语言、等级、口音与偏好判断，资格优先和引用校验，以及语言岗位不会进入 AI 批次或待确认的投递流程。测试不向真实招聘者发送消息。

## 可编辑的工作条件

在【筛选规则】的【你想要的工作条件】中自由添加、修改、启用和删除条件，每条写一个明确要求。例如：不做销售、只接受白班、必须缴纳五险一金、每天工作不超过七小时。目前最多20条，每条2至500字。

【加入八小时·双休·无经验】和单项按钮是快捷预设，可随时修改或删除。修改预设文字后会按新文字评估，不再套用原预设的判断。条件保存在本机配置，重启后恢复；之前的三个开关会迁移成列表。

每条已启用的条件都必须单独符合，并有本岗位描述或岗位字段中的原文依据，才允许自动投递。模型漏评、重复评估、捏造引文、信息缺失或描述冲突时，岗位会进入【待确认岗位】，不占投递配额，也不会标记“不合适”。明确不符合则跳过。预设八小时只扣除明确写出的休息时间，大小周不算每周双休；无经验要求会替代旧的经验年限白名单。

如果不限定职业，在【开始投递 → 手动指定目标】勾选【根据工作条件找岗位】，自选目标留空，由 AI 选择最多三个官方方向；自行选择的目标优先使用。选择关键词搜索来源时，选项为【不限岗位，按工作条件找】，搜索词仍可自己填写；仅自定义条件且搜索词为空时，浏览所选城市岗位，不会把“不做销售”等排除条件误当搜索词。城市、学历、薪资、需求词和淘汰词等仍生效；可点击【薪资改为不限】清除旧薪资范围。

待确认列表保留逐条依据和岗位链接，提供每条岗位的【投递】以及勾选后的【投递所选】。点击表示你选择先投递尚未确认的工作条件；程序重新读取该岗位及公司资料，仍检查行业、语言等排除条件，不重复请求 AI。记录在确认沟通成功后移除；未发送、停止或配额不足的记录保留。共用自动投递的任务锁和每日上限，已沟通岗位不重复发送。招聘描述仅代表招聘方的说法，真实工时和休息安排仍需向招聘方核实。

### 经验筛选

经验默认使用宽泛模式：BOSS 的“1—3年”等列表标签不直接淘汰岗位，也不以旧配置中的经验范围作为隐藏门槛。“经验优先”和正文普通经验年限会保留待确认；正文明确允许无经验时，优先使用正文。只有明确要求必须具备经验、无经验勿投等硬性条件才判为不符；正文自身冲突仍需确认。缺少依据的岗位继续保留待确认，不自动当作符合。设置中的“经验筛选方式”可切回严格模式并选择经验范围，或继续使用宽泛模式。该选择不放宽金融、助贷、销售等排除条件。

验证经验规则：在 server 目录运行 `npm run test:experience`；覆盖14种宽泛经验表述、严格模式、旧配置迁移，以及经验放宽后金融和助贷仍先淘汰的情况。

### 排除行业、公司与销售职责

排除条件在“待确认”和 AI 暂存之前执行：读取实际详情的标题、公司和标签，检查完整职位描述、公司行业、公司页介绍及经营范围。金融会识别银行、证券、保险、信贷、投资/融资、助贷等相关业务；销售会识别电销、网销、实际销售任务和邀约试听课等课程营销职责。可继续在排除词中添加其他词，也可在工作条件或手动要求中填写“不考虑某行业”“不做某岗位”。复合条件中的明确否定项先执行，其余条件继续独立验证。

列表右侧详情没有公司行业时，从实际详情的岗位链接读取完整职位页，再沿该公司的链接读取公司页。行业写成“咨询服务”“商务服务”等时，仍会检查助贷、贷款中介、融资咨询等业务。宽泛行业且没有公司简介时，保留“公司主要业务需确认”，不会据此自动投递。采用详情与公司页的真实信息；资料不可读时保留待确认。已明确命中排除项时不继续读无用页面，也不请求 AI。同一公司初筛资料可复用5分钟；暂存岗位发送前强制重新读取公司页。

社保福利和普通银行对账不会当作金融业务；经营范围中的销售许可、办公房产租赁、自有资金投资、明确禁止的金融业务也不会单独作为排除对应行业的依据。销售排除按该岗位的实际职责判断，公司拥有销售许可不代表所有岗位都是销售。

“金融科技”等技术应用领域、银行客户、银行系统开发不会单凭提及就判为公司主营金融。纬致芯创科技介绍中的数字化运营、产品工程及AI/大数据/金融科技/医疗应用按技术领域处理；真实金融行业、助贷、贷款撮合和实际金融经营仍排除。主营旅游等非金融业务明确时，宽泛经营许可中的“投资咨询”不单独判金融。明确添加“金融科技”等字面排除词仍按用户设置执行。

新待确认记录保存公司行业、完整描述及已核查的公司页业务依据。修改排除条件后，列表重新筛选，命中的旧记录会被移除并保留本地备份；没有明确排除依据的记录继续保留。备份及业务记录只存在 `data/`，不纳入 Git。

在 server 目录运行 `npm run test:exclusions`、`npm run test:industry`、`npm run test:delivery-exclusions`，验证行业与职责排除、公司页读取、误判保护、待确认重筛及发送前公司业务变化。测试使用虚构页面和模拟评估，不调用真实 AI 或联系招聘者。

验证：`cd server` 后运行 `npm run test:work-conditions`、`npm run test:work-conditions-ui`、`npm run test:batch`。测试使用虚构岗位和模拟投递，不联系真实招聘者。

## 初筛、暂存和批量评估

投递流程先打开详情，用脚本检查详情中的城市、学历、经验、薪资、需求词、排除项和工作条件，再按需要核查公司页。明确不符、公司没有介绍或职责不明确的岗位按设置在本地处理。通过初筛的岗位默认参与 AI 批量评估，包括仅按工作条件找岗位的情况；AI 检查具体职责、资格与逐条工作条件。脚本已有的明确证据优先保留，缺少依据不能由模型推测成符合；有原文依据的其他表述可由 AI 判断，仍无法确认或存在冲突的岗位进入待确认。

需要 AI 的岗位先暂存，默认每5个合并为一次请求，共用一份完整简历和要求；最后不足一批也会处理。在【设置 → 先初筛，再批量评估】可调整每批1至10个岗位。岗位与公司资料的总长度超过36000字时自动缩小批次；单个岗位连同公司资料超过36000字时留待确认，避免删掉末尾要求。每个结果按独立岗位编号对应；漏评、重复编号、无效结论或引用其他岗位的描述时不投递。发送前重新读取原岗位，内容或身份变化则跳过旧评估。

本地规则支持常见工时阈值、每周双休、无经验、不做销售、白班/不上夜班、五险一金和不加班的明确单项表述。条件列表仍可自由增删改；脚本不能完整理解的表述交给 AI；复合条件必须完整验证，不能因通过局部检查就认定整条满足。可添加字面文本规则，例如“必须包含：React”“不得包含：劳务派遣”，这些仅判断对应页面字段是否出现原词，不代表已经核实公司线下实际情况。

网页模型的简历分析、改写、岗位评估和连接测试共用串行队列，默认从上一轮结束后等待30秒再发下一次请求，可调整为10至300秒。网页返回限流时不重试，遵守其 Retry-After 等待时间，投递任务暂停。等待及请求可被停止；停止排队任务无需等待其他正在执行的请求结束。

操作节奏由内部策略自动管理，界面与配置 API 不再提供浏览间隔、操作次数、休息时长或滚动额度设置；旧字段自动清理，每日投递数仍可设置0–150。参考[牛人快跑固定版本源码](docs/niuren-kuaipao-reference.md)的累计工作后休息机制：本项目所有 BOSS 页面共用原生动作队列，连续60次操作后完整休息15分钟，计数跨重启保留。一般动作最少间隔2秒，导航同类6秒、路线同类10秒、沟通和反馈15秒；每分钟12次、每小时240次动作，每小时10次沟通/反馈/保存。岗位选择间隔在内部管理，详情和 AI 用时计入，“继续沟通”保持及时确认。这些是本项目工程限制，统计单位与上游检查点不同，不是官方安全阈值。

HTTP 429、频繁提示、验证码、账号限制或人工报告封禁会持久停止 BOSS 自动操作。Retry-After 与等待时间结束、验证码消失、页面关闭或重启，都不会自动解除停止状态。任务停止会取消未执行动作；被封账号不能用来做实测。封禁应通过平台核实或申诉。在工作台明确确认平台已恢复后，系统只读取已有页面核对，不自动刷新或试探；解除本机停止状态仍不会自动开始或恢复任务。前述节奏不能保证账号不被限制。

已经评估通过的岗位不增加模拟阅读停顿。“已向BOSS发送消息”弹窗是有效发送确认，随后及时点【继续沟通】；不会再向会话输入框补发一条。若已确认发送但继续按钮失败，先记配额并移除待确认记录，再停止批次以防重复投递。公开依据和实施边界见 [操作频率研究](docs/boss-operation-rate-control.md)。

## 保留原 PDF 排版优化并上传附件

在简历分析页选择原 PDF 文件，然后选择官方目标岗位，进入【简历优化】；可以跳过简历分析。编辑器只润色可编辑的经历正文，保留原页数、页面尺寸、字号、章节位置、照片、姓名、联系方式、教育及原数字事实，并优先复用原嵌入字体。姓名、联系资料、学校和公司标题留在本机；经历中的对应名称以占位符发送给当前模型。模型结果保存在本机，同一份原文件与目标的排版重试不会重新请求模型。

生成后可查看每页预览、润色前后和下载原版式 PDF。点击【上传到 BOSS】通过平台原生附件入口选择文件、确认添加，并核对附件列表的新编号与文件名。附件已满时必须选择替换项；只备份和替换所选文件。未确认保存的提交不自动重放，下次先核对原结果；上传前的明确失败可尝试恢复旧附件。附加的同步招聘者或更新在线简历提示会关闭。当前投递任务结束后再上传，避免操作互相干扰。

PDF 编辑组件需 Python 3.10+，首次在项目目录运行 `npm run setup:pdf`。组件安装在忽略 Git 的 `vendor/pdf-runtime/`；原文件、优化稿、缓存和旧附件备份保存在 `data/`，不纳入 Git。PyMuPDF 的上游许可为 AGPL-3.0 或商业许可，见 [官方许可说明](https://pymupdf.readthedocs.io/en/latest/about.html#license-and-copyright)；本项目 PDF 功能使用该组件，不改变其许可。
