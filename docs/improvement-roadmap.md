# 系统改进总任务

更新：2026-10-12。此清单承接原始系统反思；沟通跟进等后续功能是子任务，不能替代搜索、筛选和恢复改进。

历史分析：[原始反思](system-reflection-2026-10-12.md)、[求职功能研究](job-search-feature-research-2026-10-12.md)。早期统计属于当时快照，不能作为新版命中率。

| 原始问题 | 本轮实现 | 验收与边界 |
| --- | --- | --- |
| 列表变化导致通过岗位丢失 | 按岗位链接恢复独立详情，重新核对字段、公司与地址 | 隔离测试通过；真实新版投递待验收 |
| 停止、休息或重启丢失候选 | 持久化候选、来源、事实快照、规则指纹、状态与处理经过 | 跨实例恢复测试通过；应用重启不自动投递 |
| 技术错误转嫁人工 | 详情失败、AI 编号/格式错误进入系统恢复，有限退避重试 | 网络与格式失败测试通过；3次仍失败保存并让其他候选继续 |
| 老技术待确认池 | 主动开始时保存旧记录至候选台账，再移出人工队列 | 原记录保留在台账；按本次资料与条件重读评估，不沿用旧通过结论 |
| 统计混淆搜索与命中 | 去重发现、详情、历史通过、确认沟通、待恢复、待决定、发送待核对、收到回复分开显示 | 重读3次只计1个浏览岗位；旧版本未保存的历史扫描不可还原 |
| 搜索来源僵化 | 轮转探索来源，按去重通过与确认沟通分配12–30个新岗位的后续轮次 | 低命中来源未耗尽即可切换；每来源最多8轮，不生成用户未选的岗位来源 |
| 大量条件缺失就人工复核 | 每条条件可选择投递前必须确认／投递后追问／仅作偏好 | 默认与旧条件仍为必须确认；追问需启用并开始自动跟进，明确冲突仍淘汰 |
| 重复问 AI | 有效评估保存至候选台账；事实、规则或求职资料改变就失效 | 跨重启缓存、条件变更、事实变更测试通过；有效期24小时 |
| 投递后缺失推进 | 原沟通模块保留；台账与面试/录用记录衔接 | 消息 DOM 只读已验证，真实自动发送仍未验收 |
| 面试与录用管理 | 阶段、面试时间/地点、日历导出、录用答复截止与条件比较 | 本地持久化和界面验证；不自动承诺面试或接受录用 |
| 简历版本 | 保存各次上传原文件，标注名称/目标、切换投递版本、关联求职记录 | 本地存储与界面验证；版本记录不等于简历优化 |

## 使用

- 更新后构建并启动，桌面后台版本为33。
- 在筛选规则中给每条条件选择处理方式。原有必备资格、城市、薪资、学历、排除项和距离限制继续执行。
- 主动开始投递会先恢复与当前求职资料和来源匹配的未完成岗位，再继续扫描。
- “求职进度”显示系统恢复与处理经过；技术记录不需要用户替系统判断。
- “发送待核对”只有实际检查会话后才能标记已沟通或未发送，程序不盲目重发。
- 在“沟通跟进”启用、保存并开始自动跟进后，未知可追问条件才会实际发送问题。
- 面试与录用的具体安排由用户记录；日历导出默认时长1小时，可在日历软件中调整。
- 简历版本切换只使用保存的原文件；优化、原 PDF 版式输出和优化稿上传仍未实现。

## 验收记录

- test:candidates：链接恢复、持久化重启、AI失败续接、重复发送防护、条件分级、缓存失效、来源轮转、求职进度持久化。
- test:delivery-batching：批量与尾批、结果乱序、配额、资料变化重评、AI停止/重试、技术异常保留。
- test:work-conditions：58项工作条件与逐项证据、迁移、待确认记录。
- test:session-rest：浏览器关闭/休息/重开、页句柄刷新、验证码与登录异常。
- test:review-delivery：人工选择的单条与批量投递回归。
- test:followup：15策略场景、7消息DOM场景，均不发送真实消息。
- test:desktop：16桌面启动/关闭与协议场景。
- test:ui：8页、1320/900/390宽度、条件分级与求职进度，无页面错误和横向溢出。
