# 沟通跟进

入口在左侧“沟通跟进”。新投递确认成功后自动记录岗位、公司、时间与当时的工作条件；旧会话可手动加入。台账和消息保存在本机 `data/followup.json`，不提交 Git。

## 自动推进

- 仅跟进台账中已经沟通过的岗位。
- 无回复时按设置的间隔、次数、每日上限和北京时间时段追聊。
- 尚未明确的工作条件询问一次。读取明确回答，问题本身不算确认。
- 收到回复后停止催问；明确拒绝或条件不符时结束本地跟进，不发送“不合适”反馈。
- 自动回答仅使用用户保存的关键词与事实原文；规则冲突、缺少授权答案、面试、联系方式及附件请求留下下一步。
- 不生成自由 AI 回复，不把聊天记录发送到 DeepSeek。

默认不开启。应用重启不会自行开始。监控依赖应用保持运行。

## 使用

1. 打开 BOSS 消息并登录，选择对应沟通记录。
2. 点击“只读核对”，检查消息与岗位。
3. 设置追聊规则和允许发送的事实回答，保存后主动开始。
4. 可以随时停止，或结束单个岗位跟进。

已有草稿不覆盖；输入中出现新消息时取消旧追聊。发送意图先落盘，只有新增、编号稳定且显示已送达／已读的本人消息才算确认。结果不明时不盲目重试；重启先核对历史，仍不明时由用户核实已发送或未发送。明确未提交的操作直接取消。

沟通与投递任务互斥，沿用公共操作队列及关闭浏览器休息流程。出现登录失效或验证时停止当轮，普通打开消息按钮可拉起人工登录窗口。

## 验收边界（2026-10-12）

台账、规则、离线原生 CDP 输入/提交、消息回执、会话切换、旧草稿、新消息取消与重启去重有自动化测试。

真实登录消息页已通过只读核对：当前会话读到 4 条带编号及时间的消息，账号、联系人和岗位对应；使用公司搜索切换两个已有会话并恢复原会话通过。适配器已按求职端实际行结构、编辑器与状态标记修正。未向真实招聘方发送测试消息，真实发送仍待验收。缺少编号、账号或会话标识时不发送。

不支持自由 AI 回复、自动发送附件、承诺薪资/到岗时间或自动敲定面试；这些请求留在台账中处理。

DOM 方向和编辑器参考 [boss-cli 消息读取](https://github.com/joohw/boss-cli/blob/main/src/toolset/chat.ts) 与 [编辑器操作](https://github.com/joohw/boss-cli/blob/main/src/toolset/send.ts)。该项目主要是招聘端，不能替代求职端登录态验收；没有导入其代码或运行其 API。
