# BOSS 职位页加载中断修复

日期：2026-10-01

## 原因

打开“自动化测试 / 上海 / 岗位代码 100302”搜索页后，任务在同一秒报出“页面没有可读内容”。随后检查仍能确认 BOSS 已登录。

导航代码仅观察 URL 和 document.readyState，可能采信旧文档或页面切换过程中的状态。职位页检查又把暂时不足 20 个字符的内容直接归为不可用，跳过了异步职位卡片的等待流程。

## 修复

- 导航启用 CDP 文档生命周期事件，核对新主文档后等待 DOMContentLoaded 或 load；支持后续重定向及同文档导航。
- 暂时空白和切页时的执行上下文销毁归为加载中。默认最多等待 20 秒，职位卡片或明确的无结果提示出现后才继续。
- 持续空白报告职位页加载超时及当前地址。登录提示、安全验证、连接关闭和导航失败单独处理。
- 保存专用 Chrome 的运行实例标识，后台更新后核对标识并重新连接，保留原窗口，避免重复占用资料目录。运行记录不包含 Cookie 值。
- 增加本地 GET /api/browser/page-state，返回当前页面分类、地址、可见卡片数量和原因，不触发沟通或投递。

文档标识及事件字段依据 [Chrome DevTools 官方协议定义](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/pdl/domains/Page.pdl)。

## 验证

- TypeScript 检查及后端构建通过。
- 导航回归通过：旧文档竞态、子框架、提前到达的事件、重定向、同文档、超时、连接关闭。
- DOM 回归通过：延迟渲染、持续空白、无结果、登录提示、安全验证及原有卡片和详情确认流程。
- 真实无头 Chrome 使用离线页面通过 CDP 完成搜索入口验证，包含延迟外部脚本、异步职位卡片及自动化测试的城市和岗位参数。
- 会话重连、模拟批量任务、简历与手动要求两种入口测试通过。
- 桌面后台已更新到集成版本 11。此次更新时专用 Chrome 重开，持久化登录成功恢复；新后台确认登录有效，当前 /web/geek/jobs 页面可读取 15 张职位卡片。
- 未自动启动实际投递。更新后任务为 idle；用户可以重新启动任务。

## 浏览器生命周期补充

更新过程中进一步确认了 Windows 子进程生命周期问题：后台退出时会连带结束未独立启动的 Chrome。BOSS Chrome 和 DeepSeek 本机组件现已独立启动，人工登录窗口不随后台退出而被动关闭。参见 [libuv 官方 Windows 进程实现](https://github.com/libuv/libuv/blob/v1.x/src/win/process.c)。

真实 Chrome 生命周期测试通过：原测试后台退出后，同一个浏览器实例保持存活；新后台重连后可读取页面，断开复用连接也不会关闭窗口。测试只使用临时资料目录和离线页面。

DeepSeek 已保存账号完成一次真实 JSON 请求，模型 deepseek-v4-flash，返回预期结果，耗时 1397 毫秒。测试未提交简历或真实职位数据。
