# 人工恢复浏览器入口修复

日期：2026-10-09。

原流程在停止状态下拦截登录窗口启动，却要求恢复前看到已登录页面；浏览器关闭后形成死锁。

新增“打开 BOSS，人工处理”按钮和 POST /boss/automation-safety/open-browser。用户点击时停止自动任务，复用专用资料目录；已有安全验证页优先置前，其次是保留的异常页、登录页和业务页。现有页面不刷新、不跳转、不自动点击。没有 BOSS 页面时只打开登录页。重开浏览器不会解除停止、清空累计计数或启动投递。

人工入口释放已停止任务的内存休息门控，持久休息记录保留，后续自动任务仍经过原有休息和登录检查。普通登录、投递、上传等业务入口继续受停止状态约束。恢复确认仍只读检查已有页面，要求人工确认，不自动导航或启动任务。

休息重开后检测到登录失效或验证时，先把当前页面置前再报告停止，方便人工处理。

验证：server 的 npm run test:boss-safety 与 client 的 npm run build 通过。隔离测试覆盖停止期间复用验证页、缺少页面时创建登录页、停止记录保持、人工入口不启动任务，以及休息后异常页面置前；更新旧测试以接受此前新增的 startedAt 时间字段。没有清除真实账号停止状态或实际投递。
