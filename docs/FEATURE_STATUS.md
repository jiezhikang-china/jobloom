# 当前功能与交付边界

更新日期：2026-10-14。

## 职位来源保存与摘要修复（桌面38）

推荐页和消息“荐”来源现在通过真实配置HTTP接口的校验；保存校验与配置归一使用同一份来源定义。右侧摘要按四种来源显示，切换来源不修改现有筛选条件。

新增验证覆盖四种来源的POST、GET和重启读取，以及非法来源不覆盖原件；真实路由配合隔离浏览器，验证“选择推荐/消息来源 → 保存条件 → 启动 → 重载”，期间未访问账号或真实投递。此前只验证内部保存和投递服务，漏掉真实保存接口，现已补齐该检查。

## 待确认岗位删除（桌面37）

卡片右上角提供文字“删除”，勾选后可“删除所选”。接口先校验整批编号，再一次保存剩余记录；失败保留原件，成功同步列表数量及勾选状态。单条、批量、错误处理、刷新及重载已通过隔离验证。

GitHub上传提供[API备用方式](github-upload.md)，逐个核对本地Git对象后非强制更新远端。

## 搜索、筛选与恢复：已重构，真实效果待验收

候选台账、原链接恢复、有限 AI 重试、技术异常与人工决定分流、来源轮转和去重统计已接入。工作条件可分为必须确认、投递后追问、偏好；已有条件不被静默放宽。有效评估可跨重启复用，条件或事实变化则失效。

新增“求职进度”，支持面试时间与地点、日历导出、录用条件比较、简历原文件版本切换和关联。具体面试与录用仍由用户核对后记录。简历版本管理不代表优化稿生成已完成。

离线回归与八页界面检查通过；未进行新版真实投递，不能据此宣称真实命中率或平台限制问题已经解决。详见 [系统改进总任务](improvement-roadmap.md)。

## 沟通跟进：已接入，真实发送待验收

已实现持久化台账、只读核对、无回复追聊、工作条件询问、用户授权事实回答、发送去重与界面。共用 BOSS 操作队列和浏览器休息，并与投递任务互斥。

本轮真实登录消息页已通过只读验收：读取消息编号、方向、时间、已送达／已读状态，核对账号、联系人与岗位，并通过搜索切换两个已有会话。没有向真实招聘方发送测试消息，真实发送仍待验收。不支持自动发送附件、自动敲定面试或自由生成 AI 回复。详见 [沟通跟进](followup.md)。

## 简历优化：未实现

**简历优化当前未实现，不作为可用功能发布。**

以下流程均不承诺可用：针对目标岗位完成简历润色、保留原 PDF 版式生成优化稿、预览和导出优化 PDF、将优化附件上传或替换至 BOSS。

仓库可能保留 PDF 编辑、上传适配、相关测试或界面入口。这些属于实验实现，不能据此将整体功能标为完成。当前文档标记不删除代码，也不禁用现有入口。简历文件读取和基础分析与简历优化是不同功能。

今后至少完成以下验收后，再更新状态：

- 用户可核对修改内容，姓名、联系方式和事实信息正确保留。
- 中文字符、页数、版式和导出 PDF 经过实际文件验证。
- 明确模型请求中的数据范围，并提供可处理的失败提示。
- 原生附件上传、结果确认、失败处理和避免重复提交经过验证。

## 已接入但有边界

- 岗位筛选、公司核查、AI 评估和投递依赖 BOSS 当前网页结构及登录状态。
- 地图距离是直线距离，不包含交通路线或通勤时间。
- 系统定位可能因权限或设备能力不可用，仍可手动选点。
- DeepSeek 网页适配不是官方 API，网页协议变化需要维护。
- 脚本和 AI 只能分析已取得的招聘资料，不能核实实际劳动条件。
- 目前需要源码安装依赖并运行，未发布独立 Windows 安装程序。
