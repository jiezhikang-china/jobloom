# BOSS 直聘操作频率与退避控制研究

研究日期：2026-10-03。范围：公开官方协议、官方公开前端资源、HTTP 标准，以及本项目浏览器操作链。本次没有进行真实登录页操作、沟通、投递或“不合适”提交。

**结论：只在选择下一岗位时等待 8–20 秒，不能限制同一岗位处理中连续发生的详情点击、公司页导航、地图请求和状态写入。应对同一浏览器会话的全部页面行为统一排队，减少重复读取和写入，并在明确限频或安全验证出现时全局退避或挂起。**

下文区分已核对事实和工程建议。所有建议秒数都是可调整的工程起点，没有官方安全阈值或“不触发风控”的保证。减速也不能替代平台许可。

## 3. 建议的全操作限速

### 3.1 同一会话共享一个调度器

工程建议：所有 BOSS 页面共用队列、冷却截止时间和暂停状态，包括主岗位页、后台公司页、完整详情页、地图、期望编辑、资料编辑以及待确认投递页。操作启动时间同时满足全局间隔、类别间隔、滚动窗口预算和平台冷却要求。

采用单操作执行、无突发积攒的策略。等待期间允许立即停止；执行前重新核对目标身份、可见状态、授权任务范围和验证信号。不要用 AI 分析用时替代后续独立页面行为的限速。

单位应是一个完整行为。一次点击包含移动、按下、释放，不能在按下和释放之间插入数秒等待；一次输入包含必要的聚焦和输入，不重复消耗嵌套点击额度。队列锁放在最小完整行为处；不要锁住包含另一次排队调用的整个业务回调，以免后台详情读取公司页时发生死锁。

直接 DOM `click()`、可能触发加载的滚动、原生 Vue 路线回调、页面创建/导航均需显式经过动作入口。纯 DOM 查询、结果轮询、URL/可见性读取可维持较短本地检查间隔；检查函数不得触发新点击、导航、提交或接口请求。

### 3.2 可调整的初始配置

下面是便于实施和评审的一组工程起点，**不是 BOSS 发布或认可的允许频率**。应以平台反馈和实际负载调整，不能用实测未报错宣称安全。

| 类别 | 两次相关完整行为之间的工程间隔 | 例子 |
| --- | --- | --- |
| 一般 UI 行为 | 2–4 秒 | 弹窗开关、类别悬停与选择、切换期望、打开反馈原因列表 |
| 导航与业务读取 | 5–10 秒 | 岗位详情、公司页、完整详情页、下一页、进入或重新载入编辑页 |
| 地图业务请求 | 8–15 秒 | 新地址候选搜索、路线起点选择、重新查询公交路线 |
| 状态写入 | 15–30 秒 | 不合适反馈确定、期望保存、沟通提交 |

各类别不能各用独立队列并发执行。额外工程预算可从“全部触发行为每分钟最多 12 次、其中状态写入最多 2 次”开始；这是动作预算，不是 HTTP 请求数量，也不是官方账号额度。更长滚动窗口和单任务总预算应加入配置，达到预算后等待或结束任务。

若采用变化间隔，变化只能在类别最小间隔之后增加；用途是平滑工作负载，不是模仿用户或规避识别。休眠、重启、验证码恢复不能把积攒操作一次性补发。

## 4. 先减少操作数量与重复写入

以下均为工程建议。

- **岗位详情：**同一岗位详情仍可见且身份已确认时复用；等待渲染不变成重复点击。确需重试时只针对同一已核对目标，经过退避并限定次数；仍无法确认则暂停或跳过，记录原因。
- **公司资料：**复用本轮已读的同一公司；缓存键规范化公司路径，验证名称，并合并同一公司的在途读取。优先使用当前详情已有公司链接，减少为找链接额外打开完整岗位页。按需要过期重读；旧公司数据不能替代提交前目标核对。
- **地图：**只为通过基础筛选且需通勤判断的岗位查询；起点、终点、坐标系、方式、时间窗口一致时复用。地址输入变化采用防抖，取消尚未执行的旧查询；路线就绪前只观察，不再次选择起点或连续切换方式。记录路线时效。
- **不合适：**本地淘汰和平台反馈分别记账；已反馈岗位不重复提交。若选择公司级原因，合并同一公司的后续反馈。菜单不支持、按钮禁用或出现限频时，停止反复打开同一菜单。
- **期望：**相同配置不打开表单或再次保存；只编辑变化槽位，保存一次并等待核对。完成变更集合后做一次受限速约束的持久化验证，不为每个菜单选择刷新页面。
- **所有写入：**记录“准备、已提交待确认、确认成功、明确失败、结果不明”。超时和页面关闭不能自动等价于失败；结果不明时停止重放，等待人工核对。重启也保留待核对状态。依据是 [RFC 9110 第 9.2.2 节](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)；记账实现是项目设计建议。

## 5. 分级退避与验证停机

下表时间和次数均为工程建议。平台要求更长的等待时间时应优先遵守，不能被本地上限截短。

| 观察情况 | 建议处理 |
| --- | --- |
| 页面仍在加载，无明确错误 | 在已打开页面等待目标 DOM；不立即刷新、创建替代页或重复点击。准备超时与频率间隔是独立条件。 |
| 普通读取超时或临时网络失败 | 少量有上限的读取重试，例如先等待 30 秒，再等待 120 秒；每次仍经过全局队列。持续失败则暂停。写入结果不明不适用此规则。 |
| HTTP 429 或明确、与当前操作相关的频繁/稍后再试反馈 | 暂停会话的新页面行为；没有明确时长时可采用 1 分钟、5 分钟、15 分钟递增冷却，连续出现后挂起等待人工决定。若只读取得有效 Retry-After，等待不短于其值；有明确每日上限时遵守平台要求或停止当前任务。 |
| 403、拒绝访问或原因不明的业务异常 | 停止当前操作并分类；不把所有资源 403 都认定为账号风控，也不把权限拒绝当临时错误连续重试。关注与当前 BOSS 业务有关的响应或明确页面反馈。 |
| 验证页、可见验证码、明确安全验证或账号限制 | 冻结所有页面上的自动点击、输入、滚动、导航、路线调用和提交。保留验证页与待确认写入，显示需要人工处理，不自动解题、不更换账号或环境继续。 |
| 登录失效 | 冻结业务操作并保留现场，由人工恢复登录。不能反复刷新登录页或轮流打开业务页来检查恢复状态。 |
| 人工完成验证并确认恢复 | 先做只读状态/目标核对；保留失败计数和写入待核对记录。以较慢配置恢复，重新确认待执行目标，不补发暂停期间积攒的操作。 |

429 与 Retry-After 的语义来自 [RFC 6585](https://www.rfc-editor.org/rfc/rfc6585.html#section-4) 和 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#section-10.2.3)。没有 429、验证码短暂消失或普通 HTTP 200 不足以证明风控解除；标准允许服务器采取其他资源限制手段。[RFC 6585 第 7.2 节](https://www.rfc-editor.org/rfc/rfc6585.html#section-7.2)

提示识别应读取本次操作之后出现的可见错误弹窗、toast 或验证区域，避免整个页面任意出现“频繁”二字就暂停。若要解析业务码，必须有官方定义或对应真实公开源码，不能猜测“风控码”。后台页验证信号也应上报全局。

## 6. 实施时的验证与观察建议

优先用离线页面和可控制时间验证：主页面与后台页共用间隔；直接 DOM 点击和 Vue 回调不能绕开；纯读取不触发新请求；点击按下/释放完整；等待可停止；限频影响全会话；验证不自动恢复；写入结果不明不重放；重启不清空冷却或补发排队动作。不要用真实账号做压力测试或试探阈值。

日志记录动作类型、目标标识、开始/结束时间、等待原因、近期动作数量、缓存命中、重试次数和暂停原因。可观察当前浏览器已有响应以获得 HTTP 状态或等待提示，不复制或重放业务请求，不记录 Cookie、认证头、令牌或不必要的个人资料。

本文建议不包含验证码绕过、指纹伪造、代理轮换、账号轮换或隐藏自动化。平台许可、官方规则和明确限制始终优先于本地调度配置。


## 7. 初次实施结果（历史，现行策略见第9节）

已接入全页面单队列。默认 UI 动作间隔2秒，连续20次后休息20秒；导航同类间隔6秒、路线同类间隔10秒、反馈与保存同类间隔15秒。岗位浏览间隔继续生效，“继续沟通”确认使用短间隔。配置在筛选规则中调整，均属于工程设置，不是官方许可频率。

原生鼠标按下/释放、输入聚焦/插入作为完整动作执行。期望设置的直接 DOM 点击、滚动加载、Vue 路线回调、附件选择/保存、后台页面创建和导航均已接入。纯读取不消耗动作间隔。反馈和沟通提交在排队结束后再次核对目标；停止取消等待中的动作，暂停挡住后续动作。

BOSS 域名的429响应及与操作相关的频繁提示触发全局退避。遵守 Retry-After，默认从60秒逐次加倍，持续限频时最多900秒（更长 Retry-After 仍遵守），冷却保存在本机。任意已连接 BOSS 页面出现可见安全验证时冻结新动作，保留页面供人工完成，沿用原任务的人工恢复与只读检查流程。

附件保存前记录待核对状态，结果不明不自动重新提交，再次进入先核对新附件编号和文件名。离线测试覆盖共享队列、间隔、短休息、原生事件、停止取消、跨页验证、429来源、冷却恢复及附件结果不明后的去重。没有用真实账号压力测试或探测阈值。第8节补充分钟预算和持久停止；覆盖全部业务的提交状态机仍未全面实现。


## 8. 账号封禁报告后的修正（2026-10-03，版本25）

用户报告 BOSS 账号被封禁，已保存本机停止状态。尚无平台封禁原因原文，不能断言某一次操作是封禁原因。已删除验证码消失后自动恢复，以及频繁提示冷却到期后自动继续。

停止门控覆盖投递、待确认投递、扫码/验证、附件读取与上传、页面创建及项目页面动作，跨重启保留。登录状态观察只读取已有窗口，不启动 Chrome、创建标签或刷新。分类使用本地快照。

滚动预算默认每分钟12次动作、每小时240次动作、每小时10次沟通/反馈/保存，跨页面共用、跨重启保留。发送后的继续沟通保持短间隔，仍受停止状态约束。最近1000项操作类型、时间和结果保存在本机，不记录正文或认证值。均为工程限制，不能当作官方安全频率。

限频、验证及账号限制停止新动作，时间到期不会自动恢复。用户需先通过平台核实账号可正常使用，再明确确认；本机只读核对已有页面，解除本机停止状态不会自动运行任务。系统不能解除平台封禁，也不用被封账号测试限制阈值。安全测试使用模拟连接和虚拟时间，隔离真实账号停止记录。


## 9. Electron 与牛人快跑参考重构（2026-10-05，版本26）

源码研究及固定版本出处见 [牛人快跑参考](niuren-kuaipao-reference.md)。采用累计检查后休息和窗口关闭停止所属任务的思路，保留本项目更严格的封禁/验证/限频持久停止。

2026-10-07 长测已纠正原先过度保守的计数：约 100 次来源切换、列表加载、详情选择、反馈或提交等业务动作后休息 15 分钟，普通控件点击不计入长期休息。所有原生动作仍共用队列。2026-10-07 二次长测发现每分钟 12 次和多层等待叠加后操作过慢，当时改为普通控件与输入至少 500ms，详情同类间隔 3 秒、导航 1.5 秒、来源切换 2.5 秒、翻页 5 秒。反馈写入间隔 3 秒，沟通提交与先前写入间隔 1 秒；继续沟通按 500ms 短间隔执行。取消原先每分钟 12 次、每小时 240 次及每小时 10 次共享写入预算，删除流程层 8–18 秒选岗等待；读取页面和 AI 用时计入下一次同类操作间隔。业务计数和实际动作记录跨重启保留；旧原生动作计数不直接转换成新单位，原有平台限制继续保留。策略由 boss-operation-policy.ts 内部管理，业务 API 不能覆盖。继续沟通短确认不受普通累计休息阻塞，但仍受封禁和验证停止门控。

Electron 本地资源经 `boss-app://desktop` 加载；主进程转发私有后台 API，隔离 preload 仅暴露命名窗口命令。后台服务校验随机桌面凭据，日志、上传和 PDF 响应保持流式/二进制。窗口关闭先停止任务，工作进程与主进程的 IPC 断开也停止。没有采用上游通用异常自动重跑或额度耗尽后重试。

本地测试覆盖真实 Electron 协议、实时事件、中文 multipart、二进制响应、用户设置移除、配置迁移、累计休息跨重启和桌面生命周期。没有继续操作被封 BOSS 账号。


## 10. 人工解封确认（2026-10-06）

用户明确确认平台封禁结束后，可撤销仅由人工报告产生的本机停止记录，即使专用浏览器已关闭；恢复操作不打开浏览器、不启动任务。原先同时锁住浏览器入口并要求已登录页面才能解锁，会造成恢复死锁。已有浏览器只做被动检查，可见验证或限制继续拦截。系统检测证据与等待期限跨报告优先级保留，不能通过再次报告或关闭页面转换成免核对的人工记录。实际投递仍走独立登录检查和内部动作策略。

## 11. Windows 操作记录保存冲突（2026-10-07）

新节奏续测约一分钟时，Windows 对操作记录替换返回 EPERM，程序按本机记录保存失败停止；当时没有平台限频或验证证据。已改为唯一临时文件及有界原子替换重试：仅对 EPERM / EBUSY / EACCES 等共享锁冲突等待 10、20、40、80、160ms，原有效记录始终保留。永久错误和其他磁盘错误仍停止。停止记录使用同一写入方式。

本次先备份旧记录、未落盘记录、停止现场和测试报告，再核对未落盘记录是现有计数的续写，恢复了一个动作。仅修复这次有明确文件错误证据、且不带平台证据的本机停止；没有清空业务累计计数、平台冷却或验证记录。回归覆盖短暂锁、永久锁、原记录完整和未知磁盘错误。
长测补充：业务计数距上限仅剩一次时，先评估已有候选，再选择下一岗位，避免该次选择达到上限后将候选挡在公司页读取之前的长休息中。


## 12. 2026-10-07 再次调整操作间隔（当前）

普通控件之间至少 1 秒，输入之间 1.2 秒，同类详情选择间隔 3.5 秒、导航 2 秒、自选来源切换 3 秒、翻页 5 秒；写入动作中投递间隔 2.5 秒、不合适反馈间隔 5 秒。发送后的确认保持快速响应，不加 16 秒阅读停顿。读取和 AI 用时计入这些间隔，累计业务休息、平台明确限频与验证停止逻辑保留。这些是本机调度参数，不代表平台安全阈值。

不合适反馈仅在本地脚本用真实原文命中用户明确排除项时发出。AI 低分、经历不完全匹配、薪资/学历/城市/距离/活跃度不符不发出网站反馈。排除公司主营、行业或名称时才选公司范围；只排除岗位职责/名称时只记录岗位，避免连带隐藏公司的其他职位。
